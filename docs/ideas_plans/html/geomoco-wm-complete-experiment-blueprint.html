GeoMoCo-WM Complete Experiment Blueprint

A staged plan for visual-grounded future-motion modeling: DINO context, GeoMoCo-cVAE priors, oracle gates, shared action decoders, and long-horizon LIBERO validation.

Date: 2026-06-05 Project: Geomoco-WM Status: planning archive

Core Decision

GeoMoCo-WM should not be a VAE-only version of old GeoMoCo. It should be a visual-grounded future-motion prior whose value is proven by predictive, oracle, action-decoder, and long-horizon gates.

1. Visual Context

DINO patch tokens from RGB history, agentview, and wrist when available.

2. Grounding

EEF/proprio/task-conditioned temporal pooling into a visual grounding token.

3. Motion Prior

GeoMoCo-AE and GeoMoCo-cVAE predict future geometric motion and phase.

4. Action Bridge

Shared action decoder tests whether future motion is executable.

5. Validation

Mechanism tasks first, LIBERO-Long / LIBERO-10 only after gates pass.

Lessons From Previous GeoMoCo

What The Old DINO Line Warned Us About

  • DINO can be a strong baseline by itself.
  • Raw DINO-distance plus latent-distance fusion is brittle.
  • Low state-regression error does not preserve executable-neighbor order.
  • Phase-correct neighbors can still be action-infeasible.
  • Task7 often saturates, while task5 exposes phase/action failure.

Design Implication

Use DINO as a context source, not as the whole method. Train visual grounding to predict future motion, progress, and executable targets instead of using it only as nearest-neighbor distance.

DINO tokens -> g_t
g_t + robot history -> p(z_future)
z_future -> future geometry/progress/action

Dataset Design

Raw Episode Fields

  • RGB: agentview and wrist
  • Proprioception, EEF pose, gripper
  • Task id or language
  • Action command
  • Optional object-state teacher
  • Success and replay metadata

Window Targets

  • Future EEF SE(3)
  • Per-step EEF deltas
  • Geometric progress / phase
  • Future DINO feature
  • Action chunk
  • Optional contact/object teacher

Splits

  • Train for fitting
  • Search/dev for gate selection
  • Held-out validation for one-shot confirmation
  • No alpha or model tuning on validation

Experiment Sequence

Gate -1: Task Mining

Choose tasks with headroom, oracle replay success, phase structure, and non-saturated direct baselines.

task0 drawertask5 platetask7 stoveLIBERO-Long

Gate 0: Data And Features

Export windows, cache DINO features, and audit alignment before any model training.

Gate 1: Visual Grounding

Test whether DINO-conditioned context predicts future EEF SE(3), progress, and future visual features.

Gate 2: Oracle Motion

If ground-truth future motion does not improve a controlled action decoder over direct BC, stop the action route.

Gate 3: Future Prior

Compare AE, cVAE samples, direct residual, random, shuffled, and oracle motion on coverage and phase precision.

Gate 4: Shared Decoder

Check whether learned future motion closes part of the oracle action gap under the same decoder capacity.

Gate 5: Mechanism Closed Loop

Run task0/task5/task7 search splits, with fixed/regressed case audits and action trace diagnostics.

Gate 6: Long-Horizon Main Result

Promote to LIBERO-Long / LIBERO-10 only after Gates 1-5 pass cleanly.

Promotion And Stop Rules

Promote When

  • Visual grounding beats proprio/history on future prediction.
  • Oracle future motion beats direct BC under controlled capacity.
  • cVAE improves coverage beyond AE and direct residual baselines.
  • Learned future motion closes part of the oracle action gap.
  • Long-horizon tasks show stronger gains than short tasks.

Stop Or Redesign When

  • Direct DINO/proprio policy saturates all selected tasks.
  • Oracle future motion does not help actions.
  • Random/shuffled latent matches GeoMoCo.
  • Direct residual future dominates cVAE everywhere.
  • Search-split gains disappear on held-out validation.
